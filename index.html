Edit this resource

  1. Sign in to GitHub. A free GitHub account is required. GitHub will create a branch or fork for your proposal.
  2. Edit the resource’s YAML file. Change only the information that needs correcting and keep the existing field names and indentation.
  3. Choose “Propose changes”. GitHub will open a pull request. Automatic checks validate its structure, taxonomy values, filenames, and duplicate URLs before a maintainer reviews it.
  4. Watch for feedback. GitHub will notify you on the website and, depending on your notification settings, by email if a check fails or a reviewer responds.
YAML and catalogue rules
  • Use spaces for indentation—never tabs—and keep nested values aligned.
  • List items start with -; quote text containing : or #.
  • Keep id unchanged and ensure the filename still matches it.
  • Values under types, topics, and audiences must come from the catalogue taxonomies.
  • languages uses standard tags such as en or pt-BR; omit it when unknown.
  • maintainerEmail is a valid maintenance contact address or unknown for legacy records. Real addresses are stored in the public repository and generated catalogue data.
  • Use the resource’s stable, canonical website for url.

Suggest a new resource

You will complete a structured GitHub form.

  1. Sign in to GitHub with a (free) account.
  2. Describe the resource, provide a maintainer email, choose its topics and audiences, and enter any known language codes and access details.
  3. Submit the suggestion. Automation will validate the data, then create a pull request for maintainer review. If it cannot do so, it will reply to your suggestion with an explanation.
